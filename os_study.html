MODULE 1Ch 1–2 · OS Services

From the moment power hits the board to the system calls your programs make — what the OS is and does.

What an OS is

An operating system is a program that acts as an intermediary between the user and the computer hardware. Its three goals are to run user programs, make the machine convenient to use, and use the hardware efficiently through orderly, controlled allocation of resources.

Kernel, system programs, middleware

The kernel is the one program running at all times on the computer. Everything else is either a system program (ships with the OS) or an application. Middleware is a set of software frameworks that give developers extra services such as databases, multimedia, and graphics.

Device drivers & controllers

A computer is CPUs and device controllers connected by a shared bus. The OS has a device driver for each controller; the driver loads the controller's registers and handles communication between the OS and the device.

Interrupts: how a device says 'done'

When a device controller finishes an operation it signals the CPU by raising an interrupt. Control transfers through the interrupt vector, which holds the addresses of all the service routines. The OS first saves the CPU registers and program counter, then decides which type occurred. A software-generated interrupt from an error or a service request is a trap (exception). An OS is fundamentally interrupt-driven.

Startup & bootstrap

The bootstrap program runs at power-up. It is stored in ROM or EPROM (firmware), initializes the whole system, and loads the kernel into memory to start execution.

Storage the CPU can reach

The CPU can directly access only registers and main memory. Main memory (DRAM) is volatile and randomly accessible. Secondary storage is a nonvolatile extension that the CPU cannot touch directly.

Caching

Caching means copying information from slower into faster storage. The faster cache is checked first; if the data is there it is used directly, otherwise it is copied in. A cache is always smaller than the storage it caches.

Multiprogramming, timesharing, virtual memory

Multiprogramming keeps the CPU busy by switching to another job whenever the current one has to wait. Timesharing (multitasking) switches so fast that users interact with each job, with a target response time of less than one second. Virtual memory lets a process run even when it is not completely in memory.

Dual mode & privileged instructions

Dual-mode operation uses a hardware mode bit to mark user vs kernel mode. Some instructions are privileged and run only in kernel mode. A system call switches to kernel mode and returning resets it to user.

The timer

A hardware timer prevents a process from running forever. It interrupts the CPU after a set period, set by the OS (a privileged instruction), so control always returns to the OS.

Program vs process

A program is a passive entity (a file on disk); a process is an active entity (a program in execution). A process needs resources — CPU, memory, I/O, files — to do its work.

Multiprocessor systems

In symmetric multiprocessing (SMP) each processor performs all tasks; in asymmetric multiprocessing each gets a specific task. Benefits include increased throughput, economy of scale, and reliability through graceful degradation — the system keeps running after a processor fails.

Computing environments & cloud

Cloud computing delivers computing, storage, and apps over a network. A public cloud serves anyone who pays, a private cloud is run by a company for its own use, and a hybrid mixes both. Service models are SaaS (applications), PaaS (a software platform), and IaaS (servers/storage).

Free & open-source systems

Open-source operating systems ship in source-code form. The Free Software Foundation's GNU Public License (GPL) uses the idea of copyleft to keep derived works open. Examples include GNU/Linux and BSD UNIX.

System calls, APIs, parameters, ABI

Programs usually reach OS services through a high-level API — Win32, POSIX, or Java — rather than raw system calls. Parameters are passed three ways: in registers, in a memory block/table, or on the stack (never via the page table). The Application Binary Interface (ABI) defines how binary code interfaces for a given architecture.

I/O subsystem: buffering, caching, spooling

The I/O subsystem hides device details. Buffering stores data temporarily during transfer, caching keeps a fast copy, and spooling overlaps the output of one job with the input/output of other jobs.

Direct memory access (DMA)

DMA lets a high-speed device transfer whole blocks of data straight to memory without the CPU, generating only one interrupt per block instead of one per byte.

Virtualization

Virtualization lets one machine run other operating systems as guests on a host, managed by a virtual machine manager (VMM). It differs from emulation (used when the guest CPU type differs from the host — the slowest method) and from interpretation of non-native code. Cloud computing is built on top of it.

Operating-system services

User-facing services include a user interface (CLI, GUI, touch-screen, or batch), program execution, I/O operations, file manipulation, communications, and error detection. System-facing services include resource allocation, accounting/logging, and protection and security.

Types of system calls

System calls fall into six groups: process control, file management, device management, information maintenance, communications, and protection.

MODULE 2Ch 3–4 · Processes & Threads

A program becomes a living process with threads, state, and ways to talk to other processes.

A process in memory

A process image has four sections: text (the executable code), data (global variables), heap (memory allocated dynamically at run time), and stack (function parameters, locals, and return addresses).

Process states

A process moves through new → ready → running → waiting → terminated. Ready means it is in memory and waiting only for a processor. Waiting means it is blocked until some event occurs, such as I/O completion.

The Process Control Block

Each process is represented by a Process Control Block (PCB), which holds the process state, program counter, CPU registers, scheduling info, memory limits, and I/O status — but not boot ROM contents.

Scheduling queues

The ready queue holds processes in main memory that are ready to execute. Wait queues hold processes blocked on an event. Processes migrate between these queues as they run.

Context switch

Switching the CPU to another process saves the old process's context in its PCB and loads the new one. Context-switch time is pure overhead — the system does no useful work while it happens.

Creating processes

A parent creates children with fork(). One possibility is that the child process is a duplicate of the parent, sharing the same program and data, before optionally loading a new program.

Why processes cooperate

Reasons for cooperation include information sharing, computation speedup — breaking a task into subtasks that run in parallel — and modularity.

Inter-process communication

There are two IPC models. In shared memory the user processes themselves control communication over a shared region. In message passing they use send/receive. Direct communication names each process explicitly; indirect communication sends and receives through mailboxes (ports).

Threads vs processes

A thread shares its process's resources, so creating a thread is cheaper than creating a process and has lower switching overhead. Benefits include responsiveness, resource sharing, economy, and scalability.

Parallelism vs concurrency

Parallelism means more than one task runs simultaneously; concurrency means more than one task makes progress. Data parallelism distributes subsets of the same data across cores; task parallelism distributes different operations.

Thread libraries

The three primary thread libraries are POSIX Pthreads, Windows threads, and Java threads.

Multithreading models

Many-to-one maps many user threads to one kernel thread, so one blocking thread blocks them all. One-to-one gives each user thread its own kernel thread (used by Windows and Linux). Many-to-many maps many to many.

Operations on processes

When a process creates a child, the parent can run concurrently with the child, or wait until the child finishes. A process terminates when it runs its last statement and asks the OS to delete it; a parent may kill a child that exceeds its resources or is no longer needed.

Multicore programming challenges

Writing for multiple cores brings challenges: dividing activities, achieving balance, data splitting, handling data dependency, and testing and debugging.

Threading issues

Threading raises several issues: the semantics of fork() and exec(), signal handling (synchronous or asynchronous), thread cancellation (asynchronous or deferred), thread-local storage, and scheduler activations.

MODULE 3Ch 5 · CPU Scheduling

With many processes ready at once, who runs next — and by what rule?

CPU–I/O burst cycle

Maximum CPU utilization comes from multiprogramming. Process execution alternates between CPU bursts and I/O bursts; the distribution of CPU bursts is what scheduling cares about.

Preemptive vs nonpreemptive

Scheduling is nonpreemptive when it happens only as a process terminates or switches to waiting (cases 1 and 4). Otherwise it is preemptive. Modern systems use preemptive scheduling.

The dispatcher

The dispatcher hands the CPU to the chosen process: it switches context, switches to user mode, and jumps to the program. Dispatch latency is the time to stop one process and start another.

Scheduling criteria

Turnaround time is the total time to execute a process; throughput is the number of processes completed per time unit; waiting time is time in the ready queue; response time is the time from submission until the first response is produced.

FCFS & the convoy effect

First-Come First-Served runs jobs in arrival order. For P1=24, P2=3, P3=3 in that order, waiting times are 0, 24, 27, giving an average of 17. A long job at the front delays everyone — the convoy effect.

Shortest-Job-First

SJF gives the minimum average waiting time and is optimal, but the next burst length is unknown so it is estimated by exponential averaging. The preemptive version is shortest-remaining-time-first. SJF is priority scheduling where priority is the inverse of the next CPU burst.

Round Robin

Each process gets a time quantum q, then is preempted and placed at the end of the ready queue. With n processes, none waits more than (n−1)q. A very large quantum makes RR behave like FCFS; a tiny one wastes time on context switches.

Priority & starvation

In priority scheduling the CPU goes to the highest priority, where by convention the smallest integer is the highest priority. Low-priority jobs may starve; the fix is aging, which raises a waiting process's priority over time.

Multilevel feedback queue

A multilevel feedback queue starts a job in a high queue and demotes it to a lower queue when it uses up its whole time quantum. A plain multilevel queue instead keeps a separate fixed queue per priority or process type, with no movement between them.

Contention scope

Scheduling user-level threads within one process is process-contention scope (PCS). Scheduling kernel threads in competition among all threads in the system is system-contention scope (SCS).

Load balancing & affinity

Push migration moves a task off an overloaded CPU; pull migration has an idle CPU pull work. Soft affinity tries to keep a thread on the same CPU but gives no guarantee; hard affinity is strict. A NUMA-aware OS places a thread's memory close to the CPU it runs on.

Multicore & hyperthreading

Chip multithreading gives each core several hardware threads. On a quad-core system with 2 hardware threads per core, the OS sees 8 logical processors.

MODULE 4Ch 6 · Sync Tools

When concurrent processes touch shared data, the tools that keep them orderly.

Race conditions

A race condition occurs when the result depends on the order of execution of concurrent processes accessing shared data.

The critical section

The critical section is the code that accesses shared data. Each process has an entry section, the critical section, an exit section, and a remainder section.

The three requirements

Mutual exclusion: only one process in its critical section at a time. Progress: choosing the next entrant cannot be postponed indefinitely. Bounded waiting: a bound limits how often others may enter before a waiting process does.

Peterson's solution

Peterson's solution is for two processes; it assumes load and store are atomic and uses a turn variable and a flag array (flag[i]=true means Pi is ready). It is not guaranteed on modern hardware because instructions may be reordered for speed.

Hardware support

On a uniprocessor a critical section can be protected by disabling interrupts. The test_and_set instruction returns the original value of its target and sets it to true atomically. Compare-and-swap and test-and-set are atomic hardware instructions. These build higher-level tools such as atomic variables, which give uninterruptible updates to integers and booleans.

Mutex locks & spinlocks

A mutex protects a critical section with acquire() and release(). A basic mutex that loops while waiting is a spinlock; its drawback is busy waiting that wastes CPU cycles.

Semaphores

A semaphore is touched only by two atomic operations: wait() decrements it (and may block) and signal() increments it — originally named P() and V(). A binary semaphore behaves like a mutex; a counting semaphore ranges over an unrestricted domain. To force S1 before S2, a synch semaphore is initialized to 0. A no-busy-wait implementation uses a waiting queue with block and wakeup.

MODULE 5Ch 7 · Sync Examples

The three textbook puzzles every synchronization scheme is tested against.

The three classic problems

The classic synchronization problems used to test new schemes are the bounded-buffer, readers-writers, and dining-philosophers problems (page replacement is not one of them).

Bounded-buffer semaphores

The bounded buffer uses three semaphores: mutex = 1, empty = n, the buffer size (free slots), and full = 0 (counts filled slots). The producer first calls wait(empty) and the consumer first calls wait(full), then each waits on mutex. After updating the buffer the producer calls signal(mutex) then signal(full); the consumer calls signal(mutex) then signal(empty).

Readers-writers

Readers only read (they never modify); a writer needs exclusive access — one writer, no readers. The shared data uses rw_mutex = 1, mutex = 1, and read_count = 0. read_count tracks the readers currently reading (active readers); the first reader does wait(rw_mutex) to lock out writers. In the second variant, once a writer is ready no newly arrived reader may start. Both variants can cause starvation.

Dining philosophers

Each philosopher needs two chopsticks to eat, and the chopstick[5] semaphores each start at 1. The naive grab-left-then-right solution can cause a deadlock if everyone grabs their left stick at once.

Windows kernel synchronization

On uniprocessor systems Windows uses interrupt masks to protect global resources; on multiprocessor systems it uses spinlocks, and a spinlocking thread is never preempted. Windows also provides dispatcher objects that can act as mutexes, semaphores, events, and timers.

Dispatcher objects, events, timers

A Windows dispatcher object is signaled (available) or non-signaled (the thread blocks). An event acts much like a condition variable; a timer notifies one or more threads when its time expires.

MODULE 6Ch 8 · Deadlocks

Everyone waiting on everyone — how deadlock forms and how systems handle it.

System model

Each process uses a resource in the order request, use, release.

Four necessary conditions

Deadlock needs four conditions at once: mutual exclusion, hold and wait, no preemption (a resource is released only voluntarily by its holder), and circular wait (a chain of processes each waiting on the next). Aging is not one of them.

Resource-allocation graph

A request edge points Pi → Rj; an assignment edge points Rj → Pi. No cycle means no deadlock. With several instances per type, a cycle means deadlock is only possible.

Handling deadlocks

The methods are prevention, avoidance, detection-and-recovery, or ignoring the problem — resource caching is not one of them.

Deadlock prevention

Prevention denies a condition. Requiring a process to request all its resources before it starts attacks hold-and-wait. The most common technique invalidates circular wait by imposing a total ordering on resource types.

Deadlock avoidance & safe states

Avoidance needs each process's maximum resource claim in advance. A system is in a safe state if a safe sequence of all processes exists; an unsafe state means deadlock is possible. For a single instance of each resource, avoidance uses a resource-allocation graph.

Banker's algorithm

The Banker's algorithm handles multiple instances per resource type. Need = Max − Allocation; the Available vector has length m (resource types); the safety algorithm initializes Work to Available.

Deadlock detection

For single-instance resources, detection uses a wait-for graph (Pi → Pj). Finding a cycle in a graph of n vertices needs on the order of n² operations.

Recovery from deadlock

By process termination you can abort one process at a time until the cycle clears. By resource preemption, rollback returns a process to an earlier safe state. Always choosing the same victim causes starvation.

MODULE 7Ch 9 · Main Memory

Fitting programs into RAM: addresses, fragmentation, and paging.

Memory & protection

The CPU can access only registers and main memory directly. A pair of base and limit registers defines the legal address range of a process, checked on every access.

Address binding & logical vs physical

Binding can happen at compile, load, or run time; execution-time binding is delayed until run time. The CPU generates the logical (virtual) address; logical and physical addresses differ in the execution-time scheme. The relocation register value is added to every logical address. The hardware memory management unit (MMU) performs this logical-to-physical mapping at run time.

Contiguous allocation & fragmentation

First-fit allocates the first hole big enough; best-fit allocates the smallest hole large enough. External fragmentation is free memory scattered in unusable gaps; internal fragmentation is wasted space inside an allocation. Compaction gathers free memory together and is possible only when relocation is dynamic and done at execution time. Worst-fit allocates the largest hole, leaving the largest leftover.

Paging

Paging divides physical memory into fixed-size frames and logical memory into equal pages, which eliminates external fragmentation. A logical address splits into a page number (an index into the page table) and an offset. The page-table base register (PTBR) points to the page table.

TLB & effective access time

Without a TLB, each reference needs two memory accesses (table + data). The TLB is fast associative memory caching recent translations. With a 99% hit ratio and 10 ns access, the effective access time is about 10.1 ns. An ASID identifies the process owning a TLB entry, avoiding flushes.

Protection & inverted tables

The valid–invalid bit shows whether a page is in the process's address space. An inverted page table has one entry per physical frame instead of per page.

Swapping

Swapping moves a process out to a backing store on disk and back into memory later for continued execution.

MODULE 8Ch 10 · Virtual Memory

Pretending you have more memory than you do, and the cost when you overdo it.

Virtual memory

Virtual memory separates logical from physical memory, so the logical address space can be larger than physical memory; only part of a program need be resident.

Demand paging

Demand paging loads a page only when it is referenced. Each page-table entry has a valid–invalid bit; an 'i' means the page is not in memory.

Page faults

A page fault occurs when a referenced page is not in memory. The OS loads the page, fixes the table, and restarts the instruction that faulted. The modify (dirty) bit avoids writing unchanged pages back to disk.

Page replacement

With no free frame the OS picks a victim frame to replace. FIFO suffers Belady's anomaly, where more frames can cause more page faults. OPT replaces the page that will not be used for the longest time (farthest in the future) — the lowest fault rate, used only as a benchmark for other algorithms. LRU replaces the least recently used page — the one that has not been used for the longest time; the second-chance (clock) algorithm is FIFO plus a reference bit.

Frame allocation

With equal allocation, 100 frames among 5 processes gives each 20. Proportional allocation gives frames by process size. In global replacement a process can take a frame from another; in local replacement it uses only its own frames.

Thrashing & locality

Thrashing happens when a process's active locality exceeds available memory, so it does nothing but page in and out. Demand paging works because of the locality model.

MODULE 9Ch 11 · Mass Storage

Where the data actually lives, and how the disk arm is scheduled.

HDDs and access time

The bulk of secondary storage is HDDs and NVM devices. HDD positioning time = seek time (moving the arm to the cylinder) + rotational latency (the sector rotating under the head). A head crash is the head contacting the surface.

SSDs and flash

SSDs have no moving parts, so no seek time or latency. Flash must be erased in larger blocks before rewrite; the flash translation layer tracks which logical blocks are valid; wear leveling is needed because cells survive only a limited number of erases.

Disk scheduling

SCAN is the elevator algorithm, sweeping the arm end to end. C-SCAN jumps back to the start without servicing on the return, giving more uniform wait times. Linux uses the deadline scheduler to avoid starvation. SSTF serves the closest request first — common, but it can starve far requests.

RAID

RAID = redundant array of inexpensive disks. RAID 1 provides reliability through mirroring (a duplicate of each disk); redundancy raises the mean time to failure. A hot spare automatically replaces a failed disk. RAID 0 is plain striping with no redundancy; levels 4, 5, and 6 use block-interleaved parity.

Storage attachment

Storage is host-attached, network-attached, or cloud. NAS is accessed as a remote file system (NFS/CIFS). Cloud storage is API-based over the Internet, unlike NAS's file-system view. Host buses include SATA, SAS, and USB, plus the fast NVMe interface for flash; a storage-area network (SAN) links many hosts to many storage arrays over Fibre Channel.

Formatting & object storage

Low-level (physical) formatting divides a disk into sectors the controller can read. Object storage accesses each object via a unique object ID. The boot block loads the kernel at startup. Disk I/O is done in blocks but file I/O in clusters for efficiency; sector sparing handles bad blocks.

Volatile memory & RAM drives

DRAM can serve as fast mass storage: a RAM drive appears as a block device formatted with a file system, under user control, for high-speed temporary storage.

MODULE 10Ch 12 · I/O Systems

Getting data in and out, from polling and interrupts to DMA.

Drivers, ports, memory-mapped I/O

Device drivers present a uniform device-access interface to the kernel. A port is a connection point for a device. In memory-mapped I/O, device registers are mapped into the processor's address space.

Controller registers

The status register is read by the host to check device state; the control register is written by the host to start a command or change mode.

Polling

Polling repeatedly reads the busy/status bit in a loop. It is inefficient when the device is slow relative to the CPU.

Interrupts

An interrupt-request line is checked by the CPU after each instruction. A maskable interrupt can be ignored or delayed; some are nonmaskable.

Direct memory access

DMA moves large data blocks without the CPU, interrupting once when done. Cycle stealing is the DMA controller briefly grabbing the bus from the CPU.

Device categories & I/O modes

A character-stream device transfers one byte at a time; a block device moves whole blocks. A sequential device transfers data in a fixed order set by the device. A dedicated device cannot be shared concurrently. Blocking I/O suspends the process until the I/O completes; asynchronous I/O lets the process run while the I/O executes. Nonblocking I/O returns at once with whatever data is available.

Kernel I/O services

Buffering copes with device speed mismatches; spooling holds output for a device that serves one request at a time (a printer); caching keeps a fast copy of frequently used data; device reservation gives exclusive access to a device. Double buffering keeps two copies of the data so one fills while the other is processed.

I/O protection

All I/O instructions are privileged so user code cannot disrupt the system. The UNIX ioctl() call sends arbitrary bits to a device register. Vectored I/O performs multiple I/O operations in one system call.

Network devices

Network devices differ enough from block and character devices to have their own socket interface, which separates the network protocol from the operation and includes select(). Other models include pipes, FIFOs, and message queues.

Clocks and timers

The OS provides the current time, elapsed time, and timers. A programmable interval timer drives periodic interrupts and timed operations.

MODULE 11Ch 13–14 · File Systems

Turning raw disk blocks into named files and directories.

File attributes

Among file attributes, the name is the only one kept in human-readable form; the identifier is a unique number tagging the file within the system.

File operations

open() searches the directory and moves the entry from disk into memory; close() writes it back from memory onto disk.

File locking

A shared (reader) lock can be held by several processes at once. A mandatory lock is enforced by the OS (access denied based on locks held); an advisory lock leaves the decision to processes.

Access methods

Sequential access uses read next / write next. Direct (relative) access uses read n / write n with relative block numbers. An indexed access method (such as IBM ISAM) builds an index on a key for fast lookups.

Directory structures

A two-level directory gives each user a separate directory. Acyclic-graph directories allow shared subdirectories and files via links, which can leave a dangling pointer when a shared file is deleted. To prevent cycles, one rule is to allow links only to files, not directories. A single-level directory holds all files in one directory (naming and grouping problems); a tree-structured directory adds nested subdirectories.

File-system structure

A file system resides on secondary storage. The file control block (FCB) holds a file's metadata; in UNIX this is the inode (UNIX stores file metadata in inodes). The volume control block (superblock) holds volume details such as block count, free blocks, and block size.

Directory implementation

A hash-table directory decreases search time over a linear list; collisions need a chaining method.

Allocation methods

Contiguous allocation needs only a starting block and a length, but its weakness is external fragmentation. In linked allocation each block points to the next, but its drawback is poor random (direct) access. FAT keeps its table at the beginning of the volume; indexed allocation gathers a file's pointers into an index block.

Free-space management

In a bit vector, a 1 bit means the block is free. The counting method stores a first-block address plus a run length. ZFS uses log-structured space maps. Free space can also be tracked by a linked list of free blocks or by grouping free-block addresses in the first free block.

File protection (Unix permissions)

Protection controls who may do what — read, write, execute, append, delete, or list. Unix/Linux uses three classes — owner, group, and public — each with read/write/execute (rwx) bits, so a mode of 7 means rwx and 6 means read+write.

File-system layers

A file system is built in layers: device drivers (I/O control), the basic file system (issues block commands, manages buffers and caches), the file-organization module (maps logical to physical blocks, manages free space), and the logical file system (manages metadata, directories, and FCBs).

In-memory file structures

While a file is open the OS keeps a system-wide open-file table (one FCB copy per open file) and a per-process open-file table that points into it, plus a mount table of mounted file systems.

MODULE 12Ch 16–17 · Security & Protection

Keeping the system honest — threats, malware, and who may touch what.

Threats, attacks, breaches

A threat is a potential security violation; an attack is an attempt to breach security. Unauthorized reading breaches confidentiality; unauthorized modification breaches integrity. Unauthorized destruction of data breaches availability; unauthorized use of resources is theft of service.

Attack methods

A man-in-the-middle attacker sits in the data flow between two parties. A replay attack resends captured data, possibly modified. Privilege escalation gains access beyond what is allowed. Session hijacking intercepts an established session to skip authentication. Masquerading is pretending to be an authorized user to escalate privileges.

Malware types

A virus is code embedded in a legitimate program; a worm is a standalone, self-spreading program; ransomware encrypts data and demands payment; spyware captures user data or shows ads; a trap door is a secret way that bypasses normal security. A Trojan horse is a program that acts in a clandestine manner, misusing its environment.

Network attacks

Code injection exploits a buffer overflow in unsafe code. Port scanning automatically finds ports accepting connections. A denial-of-service attack prevents legitimate use of a system.

Security levels & Windows

Security must be enforced at four levels: physical, application, OS, and network. In Windows 10, logging in creates a security access token with the user's IDs and privileges.

Principles of protection

The guiding rule is the principle of least privilege — just enough rights for the task. An access right is the pair <object-name, rights-set>. A protection domain can be a user, a process, or a procedure.

The access matrix

In the access matrix, rows represent domains and columns represent objects. An access list is organized per object (a column); a capability list is organized per domain (a row). The design separates mechanism from policy. The lock-key scheme is a compromise between access lists and capability lists. Special access rights include owner, copy (written with *), control (change another domain's rights), and transfer (switch domains).
